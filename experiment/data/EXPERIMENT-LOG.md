### 1.2 相机与采集链路

- 采集：GStreamer 管道 `v4l2src → video/x-raw,NV12,WxH → videorate(drop-only) → 5fps → [v0.2: 附加滤镜] → jpegenc → 内存`
- 帧输出：/dev/shm/frame.jpg（每轮最新帧），后台每 2s 采样到 /tmp/frames_<tag>/（帧与轮次**无精确关联**——仅按数量分桶，这是已知缺陷）
- 板端 GStreamer 可用滤镜：videoscale / gaussianblur / videocrop / videobox / smooth（**无 noise**）

| 组件 | 版本/规格 |

| 预处理 | SmolVLM 用 **fixed_size 预处理**：统一 resize 512×512 → **视觉 token 数恒定**（与输入分辨率无关） |
| 模型 | SmolVLM-256M-Instruct-Q8_0（167MB + mmproj 99MB） |

| 缓存 | llama-server 默认 prompt cache 命中（相同请求 ~0.1s）→ 实验必须每轮新帧 |

## 3. 实验情况（修正指标口径重算，45 组）

**指标定义**（详见 `../metrics.py`，22/22 测试通过）：
- `format_word`：去首尾空白+可选末尾标点后，整条输出为单个 yes/no → **格式合规**
- `format_exact`：严格等于 yes/no（无句点）→ 本实验全部输出带句点，恒为 0，仅存档
- `semantic`：yes/no/unknown（不依赖真值）；`sem_correct`：与真值（所有组均为"目标存在"正样本）一致
- ⚠️ 全部 45 组均为**单一正样本场景**（风扇存在），`yes 率 ≠ 准确率`——无负样本对照

### 3.2 实验1 分辨率梯度（会话1，v0.1，问题A，160→1280）

| 模型 | 160×120 | 320×240 | 480×360 | 640×480 | 800×600 | 1280×960 |
|------|---------|---------|---------|---------|---------|----------|
| 256M format_word | 34/34 | 45/45 | 33/33 | 16/44 | 0/32 | 1/32 |
| 256M 语义Y | 0 | 45 | 33 | 44 | 32 | 32 |

**要点**：256M 突变点 480(100%)→640(36%)→800(0%)；500M 漂移更早（480 已有 5 句：3 否定句 "No, there is no..." + 2 肯定句）；160×120 两模型格式 100% 但语义全 No（低分辨率诚实回答，不幻觉）；耗时全梯度恒定（5.4-6.9s）→ 视觉 token 恒定佐证。

## 5. 已知数据质量问题（后续实验须修复）

1. **单正样本场景**：全部 45 组只有"风扇存在"场景 → yes 率≠准确率，无法计算特异度
2. **帧级伪重复**：相邻帧高度相关（同场景同 server 连续采样），Fisher 检验隐含独立性假设不成立 → 现有 p 值降级为"探索性"
3. **跨会话基线漂移**：同配置 256M@640 t=0.1 三会话 36%/45%/67%（A 组 45%↔9%）→ 会话内对照优先
4. **帧-轮次无精确关联**：2s 采样 vs 6.5s/轮，仅按数量分桶
5. **模糊组无 sham 对照**：σ 效应与 videoconvert/重编码管线效应未解耦
6. **图文顺序混杂**：C 客户端 text→image vs 静态脚本 image→text，静态/在线差异未隔离
7. **固定运行顺序**：温度 0→1、措辞 A→F 顺序运行，与时间漂移混杂
8. **板端密码硬编码**：board.py 明文凭据已入 git（需换密码+改环境变量）
9. **A 组日志覆盖**：已修复（双版本恢复），后续命名须含 session ID
