## 结论

1. **图文顺序是输出形态的完全决定因素**（t=0.0 下）：text→image 100% 描述句，image→text 100% 单词
2. **text→image 在负场景 20/20 幻觉**：先看问题再看图时，模型把任何图像读成"风扇存在"的确认
   ——引导性问题压倒图像证据（text→image 在两种场景输出完全相同的句子模板）
3. **image→text 在两个场景 40/40 格式合规 + 语义全对**：图像优先时模型是诚实的观察者
4. **对历史数据的重新解读**：
   - C 客户端链路（text→image）= 引导式 → 640×480 高细节下产出描述句（"格式崩塌"的主要形态来源）
   - Python 静态脚本（image→text）= 观察式 → 永远单词
   - "静态图不复现/实时帧才复现"的差异主要是**图文顺序混杂**，非输入实时性
   - 但分辨率仍有残余效应：历史 C 链路 320×240（text→image）仍 100% 单词 → 顺序×细节量交互
     （低细节下"引导式确认"退化为 "Yes." 单词；高细节下扩展为描述句）
