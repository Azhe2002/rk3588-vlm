### 2.2 rk3588-vlm v3 程序架构

```
┌───────────┐     ┌──────────────────┐     ┌───────────────┐
│ camera.c  │ ──▶ │   main.c         │ ──▶ │ result_parser │
│ (持久管道) │     │  (每 N 秒推理一次)  │     │ (单词边界解析) │
│ GStreamer │     │         │        │     └───────────────┘
│ fdsink    │     │         ▼        │
│ 5fps流解析│     │   llama_server.c  │
└───────────┘     │  (HTTP 常驻服务)  │
                  └──────────────────┘
```

| 模块 | 功能 |
|------|------|
| camera.c | 持久 GStreamer 管道 → 内存帧 → 原子写盘 → 异常自动恢复 |
| llama_server.c | 常驻 llama-server + HTTP 推理，模型只加载一次；调用 `/v1/chat/completions`，图片用 base64 data URI 内嵌 |
| main.c | sigaction 信号安全 + strtol 严格校验 + CLOCK_MONOTONIC 计时 + `--camera` 参数 + 相机自动重启 |
| result_parser.c | 单词边界逐行解析，防 "not"/"nobody" 误判，冲突检测 |

### 2.3 运行环境

```bash
export LD_LIBRARY_PATH=/userdata/llama/bin
# 杀残留进程
killall -9 rk3588-vlm 2>/dev/null; killall -9 llama-server 2>/dev/null
```

## 4. Qwen2-VL-2B 转换（2026-08-05 完成）

### 4.1 输入

`~/workspace/Qwen2-VL-2B-HF/`（HF 原始权重，4.2G，safetensors 分片完整）
- 架构：`Qwen2VLForConditionalGeneration`，model_type `qwen2_vl`
- 本地转换环境：`~/workspace/.venv-gguf`（Python 3.14 + torch 2.13.0+cpu + numpy + transformers 5.14.1 + pyyaml + sentencepiece + protobuf）

### 4.2 转换命令

```bash
cd ~/workspace/llama
# 主模型（不带 --mmproj）
.venv-gguf/bin/python convert_hf_to_gguf.py ~/workspace/Qwen2-VL-2B-HF \
  --outtype f16 --outfile ~/workspace/models/Qwen2-VL-2B-Instruct-f16.gguf
# mmproj（带 --mmproj 只导出视觉投影）
.venv-gguf/bin/python convert_hf_to_gguf.py ~/workspace/Qwen2-VL-2B-HF \
  --outtype q8_0 --outfile ~/workspace/models/mmproj-Qwen2-VL-2B-Instruct-q8_0.gguf --mmproj
# 主模型量化 Q4_K_M
~/workspace/llama/build/bin/llama-quantize \
  ~/workspace/models/Qwen2-VL-2B-Instruct-f16.gguf \
  ~/workspace/models/Qwen2-VL-2B-Instruct-Q4_K_M.gguf Q4_K_M
```

> ⚠️ 坑：`--mmproj` 模式下只导出视觉投影（输出加 `mmproj-` 前缀）；主模型须单独转换（不带 `--mmproj`）。
> ⚠️ 坑：新版 llama-quantize 不支持 CLIP 架构（mmproj），mmproj 用 convert 脚本 `--outtype q8_0` 直接导出，别用 llama-quantize。

### 4.3 产物

## 5. YOLO + LLM 方案（讨论中，未实施）

### 5.1 动机

- VLM 方案慢（8-60s/帧）且不准（50-75%）
- 板子 NPU 闲置，RKNN 运行时已就绪
- 工业检测目标固定，适合专用检测器

### 5.2 架构

```
相机帧 → YOLO (RKNN NPU, 5-30 FPS)
            │  检测目标: box(箱体)、lidless_box(无盖箱)、pallet(托盘)、
            │           goods_stack(货堆)、trash_bin(垃圾箱)
            ▼
      结构化结果: [box×N @(x,y,w,h), lidless_box×1 @...]
            ▼
     规则层(几何判断) + LLM(逻辑仲裁)
            ▼
     "no - 发现1个无盖箱" / "空托" / "未填满" / "未满货"
```

### 5.3 关键洞察

4 个测试任务大部分**不需要 LLM**，YOLO + 几何规则可解：

| 测试 | 判断方式 |
|------|---------|
| test1 | 存在 lidless_box 目标 → no（纯规则） |
| test2 | 托盘框内是否有货物目标（IoU 重叠） |
| test3 | 垃圾箱框内填充高度比例 |
| test4 | 箱体堆叠层数（框高度/单箱高度） |

准确率预估 95%+，亚秒级实时。LLM 用于：多条件组合判断、边界兜底、新任务快速迭代。

### 5.4 方案对比

| 方案 | 速度 | 准确率 | 开发成本 |
|------|------|--------|---------|
| A. YOLO + 规则 | <1s 实时 | 95%+ | 中（需训练/标注） |

| C. Qwen2-VL-2B（已转换） | 30-60s/帧 | 50-70% | 低（零训练） |

## 6. 交叉编译速查

### 6.1 关键规则

- **必须用 `debian:bullseye`**（glibc 2.31）作交叉编译基础镜像，勿用 Ubuntu 22.04（glibc 2.35）或 rk3588-builder
- Docker 内安装：`g++ g++-aarch64-linux-gnu cmake git make`
- 交叉编译用 `-j1`（-j2+ 可能 OOM）
- 编译后验证：`strings <binary> | grep GLIBC_ | sort -Vu | tail -1` 应 ≤ GLIBC_2.31
- CMake 外部库（libcurl 等）：须显式指定 `-DCURL_LIBRARY=/usr/lib/aarch64-linux-gnu/libcurl.so -DCURL_INCLUDE_DIR=/usr/include/aarch64-linux-gnu -DCMAKE_FIND_ROOT_PATH=/usr/aarch64-linux-gnu`
- llama.cpp ARM64 编译关键参数：`-DCMAKE_TOOLCHAIN_FILE=toolchain-aarch64.cmake -DGGML_NATIVE=OFF -DGGML_CPU_ARM_ARCH=armv8-a -DGGML_OPENSSL=OFF -DHTTP_ENABLE_OPENSSL=OFF -DHOST_CXX_COMPILER=/usr/bin/g++ -DLLAMA_BUILD_SERVER=ON`

### 6.2 部署到板子

- 二进制 → `/userdata/llama/bin/`，模型 → `/userdata/llama/models/`
- `/userdata` 是 root 所有，先 `sudo mkdir -p && sudo chown -R linaro:linaro /userdata/llama`
- 动态库 + 符号链接：`libllama.so → libllama.so.0 → libllama.so.0.0.1`（详见 rk3588-vlm-deploy 技能）

### 6.3 板端 shell 坑

- popen 里用 `export LD_LIBRARY_PATH=/x; cmd`，不要 `LD_LIBRARY_PATH=/x cmd`（Dash/BusyBox 会失败）
- gst-launch 静音要 `>/dev/null 2>&1`（仅 2>/dev/null 不够）
