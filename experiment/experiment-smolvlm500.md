# 实验：SmolVLM-500M 板端连续采图推理性能测试

> 实验日期：2026-08-07
> 测试平台：RK3588S (Debian 11, 192.168.1.8)
> 测试程序：`/userdata/llama/bin/rk3588-vlm` (main 主程序, v3)

---

## 1. 实验目的

- 用与 256M 完全相同的测试方法复测 SmolVLM-500M，建立同口径性能基准
- 作为对比基线（历史数据 8-9s/帧 为固定图片首帧测量值，本次用 main 主程序重新实测）
- 与 SmolVLM-256M 对比：速度差异、识别准确率

## 2. 测试配置

| 项目 | 值 |
|------|-----|
| 模型 | `SmolVLM-500M-Instruct-Q8_0.gguf` (417MB) |
| mmproj | `mmproj-SmolVLM-500M-Instruct-Q8_0.gguf` (104MB) |
| 推理服务 | llama-server (板端常驻, port 8088) |
| 相机 | /dev/video22, 320×240, 5fps |
| 推理间隔 | 1s（实际被推理时间淹没） |
| Prompt | `Is there a black industrial fan in the center of the image? Please answer only yes or no.` |
| 系统提示词 | 默认工业检测模板（目标: industrial items, 场景: factory warehouse, dim lighting） |
| 测试图 | 实时采集帧（黑色工业风扇画面，与 256M 测试同一场景） |

> ⚠️ 与 256M 实验完全同口径：同程序、同分辨率、同 prompt、同场景、同间隔。

## 4. 统计结果

| 指标 | 数值 |
|------|------|
| min | 6.14s |
| max | 7.40s（首轮含模型加载残余） |
| **平均（#2-#10）** | **6.18s/帧** |
| 10/10 识别率 | 9/10 = **90%**（#5 误判 NO） |
| 等效帧率 | ~0.16 FPS |

> 程序实际运行 130.92s，共推理 21 次；#11-#21 耗时同样稳定在 6.1-6.2s 左右（数据见板端 `/tmp/main_vlm_500.log`）。

## 5. 关键发现

1. **真实单帧耗时 ≈ 6.2s**（首轮 7.40s 含首次加载开销）：main 主程序每轮重新取帧，无 KV cache 命中，全部为真实推理时间
2. **耗时构成**：图片编码（约 4.5s）+ 生成（约 1.7s）—— 生成阶段明显长于 256M
3. **稳定性好**：除首轮外 9 轮波动 <1%
4. **识别 9/10**：第 5 轮误判为 NO（同画面其他 9 轮均 YES），说明 500M 在此任务上仍有小概率不稳定
5. **对比历史固定图数据**（8-9s/帧）：main 主程序实测更快（6.2s），可能与 320×240 分辨率及 prompt 简单有关
