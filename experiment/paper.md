# Content Order, Not Resolution, Determines Yes/No Format Compliance in an Edge-Deployed Small Vision-Language Model: A Paired-Frame Case Study on RK3588

> **状态**: v0.5 机制重述版（2026-08-13）
> **核心变更**: 经同帧配对消融（S2-E1 2×2）与 image→text 固定分辨率重扫（S2-E2-RES），原"分辨率→格式遵循崩塌"被重新归因为**图文顺序主效应 × 输入细节量调节**；分辨率本身在正确顺序下无格式效应。
> **数据基础**: 45 组历史日志（修正指标重算, `results_corrected.csv`）+ Stage2 三项新实验（S2-E0/E1/E2-RES）；全部原始数据、重算脚本与实验报告在 `experiment/`。

## 摘要 (Abstract)

在边缘设备上部署的小型视觉语言模型（VLM）常被要求输出机器可解析的严格格式（如仅 "yes"/"no"）。本文报告一个在 RK3588S + llama.cpp + SmolVLM 栈上系统追踪的案例研究：初始观察中，输入分辨率从 320×240 提升到 640×480 时，格式遵循率从 90–100% "崩塌"至 0–10%，且强化 prompt 无效。通过修正指标口径、同帧配对消融与冻结帧重扫，我们发现该现象的真实结构是：

1. **图文顺序是输出形态的完全决定因素**（2×2 场景×顺序配对，McNemar p = 1.9×10⁻⁶）：text→image（问题在前）100% 产生描述句，image→text（图像在前）100% 产生单词；
2. **text→image 顺序造成确认幻觉**：在风扇不存在的场景，模型 20/20 断言 "There is a black industrial fan in the center of the image."——引导式提问压倒图像证据；
3. **image→text 顺序下分辨率梯度完全平坦**：160×120 至 1280×960 全部 100% 格式合规，仅 160×120 出现干净的二值感知阈值（全 "No."）；
4. 视觉 token 数恒定（fixed_size 预处理统一 512×512），耗时恒为 6.1s，排除 token 膨胀机制。

**关键词**: Vision-Language Models; Instruction Following; Content Order; Confirmation Hallucination; Edge Deployment; SmolVLM; RK3588

## 1. 引言 (Introduction)

### 1.1 背景

小型 VLM（<1B 参数）被广泛部署于边缘设备（RK3588 类 SoC）执行实时视觉检测。受控自动化场景要求模型输出机器可解析的严格格式（单一 yes/no），而非自由文本。这类输出格式约束依赖模型的指令遵循能力。

### 1.2 问题陈述与发现路径

2026-08-07 的初始板端实验观察到：SmolVLM-256M/500M 在 640×480 输入下，对 "Please answer only yes or no" 的遵循率从 320×240 下的 90–100% 骤降至 0–10%，输出变为完整描述句，严厉 prompt 无效。该观察排除了解析器 bug（原始输出可见）、感知退化（语义始终正确）与 prompt 强度不足。

在将初始观察整理为论文的过程中，我们执行了指标口径修正、数据完整性审计（9 项，§3.4）与三项受控实验（S2-E0 能力探测、S2-E1 图文顺序 2×2 消融、S2-E2-RES 顺序固定分辨率重扫）。结果表明：**初始的"分辨率崩塌"现象实为图文顺序（引导式提问）与输入细节量的交互效应**。这一重述将问题从"输出格式控制失效"转写为"引导式提问下的确认偏误与描述漂移"，具有更具体的机制故事与更直接的工程解法。

### 1.3 贡献

1. **修正后的完整数据集**：45 组历史实验按独立指标（format_word / semantic_label，§3.3）重算并公开——此前主指标混淆了"格式合规"与"可解析为 Yes"；
2. **因果定位**：同帧配对证明图文顺序是输出形态的完全决定因素（p=1.9×10⁻⁶），并首次报告 text-first 顺序下的**确认幻觉**（负场景 20/20 断言目标存在）；
3. **工程可用的解法与边界**：image-first 顺序在 6 档分辨率全部实现 100% 格式+语义双合规；grammar 约束在板端实测可用（S2-E0）；
4. **方法论记录**：静态/在线混杂、跨会话漂移、伪重复检验等 9 项数据质量问题及修复方案。

## 2. 相关工作 (Related Work)

### 2.1 指令遵循与格式控制

LLM 指令遵循已被广泛研究（Ouyang et al., 2022）；结构化输出通常靠 prompt 约束或约束解码（guidance、outlines）。多模态指令遵循与输出约束近期受关注（MM-IFEngine, arXiv:2504.07957）。但**内容顺序（图文先后）对格式遵循与事实性的影响**在边缘部署场景少有系统报告。

### 2.2 小模型的能力边界

小模型存在容量瓶颈，多任务竞争（感知 vs 指令）时顾此失彼（LIMA, Zhou et al. 2024 用于对齐背景；非小模型容量证据）。本文的确认幻觉可视为该瓶颈在引导式提问下的极端表现。

### 2.3 视觉编码与分辨率

现代 VLM 将图像切 patch 投影为视觉 token。**关键实现细节**：本实验所用 llama.cpp 7af4279 对 SmolVLM 采用 fixed_size 预处理（统一 resize 512×512），视觉 token 数与输入分辨率无关——"token 膨胀"假设（H1）在本栈上不成立，分辨率只能通过**图像内容细节**起效（§4.6 耗时恒定佐证）。

### 2.4 边缘部署中的 VLM

RK3588 + llama.cpp 的工程实践已有报告，但输出格式鲁棒性的系统研究缺失。

## 3. 方法 (Methods)

### 3.1 硬件与推理栈

| 组件 | 规格 |
|------|------|
| SoC | Rockchip RK3588S（板端 192.168.1.8） |
| OS | Debian 11, GLIBC 2.31, 7.7 GB RAM |
| 推理引擎 | llama.cpp **commit 7af4279**（soname 0.15.3 系；CPU, -ngl 0, 8 线程, 常驻 server :8088） |
| 模型 | SmolVLM-256M-Instruct-Q8_0（167MB + mmproj 99MB）；SmolVLM-500M-Instruct-Q8_0（417MB + mmproj 104MB） |
| 相机 | /dev/video22, MIPI CSI, NV12, 32×32–3840×2160 |
| 预处理 | **fixed_size：统一 resize 512×512，视觉 token 数恒定** |

### 3.2 测试程序与请求协议

- 程序 `rk3588-vlm`（C）：v0.1 支持 `--width/--height/--question/--strict`（temperature 固定 0.1）；v0.2（2026-08-12）增加 `--temp` 与 `--gst-extra`（GStreamer 滤镜插于 jpegenc 前）。
- **请求参数**：`max_tokens=16`（早期稿误写 32，已更正）；temperature 默认 0.1（v0.1）/ 可调（v0.2）；**content order：C 客户端为 text→image，早期 Python 静态脚本为 image→text**——此差异是本文核心发现的源头（§4.7-4.9）。
- 系统提示词（固定）："You are an expert in recognition... Please respond with only 'yes' or 'no'. Detection target: industrial items. Scene: factory warehouse, dim lighting."
- 问题 A（默认）："Is there a black industrial fan in the center of the image? Please answer only yes or no."
- 每轮端到端 5.4–6.9s（≈0.16 FPS；瓶颈在视觉编码固定开销，"实时"指在线相机链路，非帧率）。

### 3.3 指标定义（修正口径，本文全部数据按此重算）

| 指标 | 定义 | 依赖真值 |
|------|------|---------|
| `format_word` | 去首尾空白及允许的末尾标点后，整条输出为单个 yes/no | 否 |
| `format_exact` | 严格等于 yes/no（无标点；本模型恒带句点，实测恒 0，仅存档） | 否 |
| `semantic_label` | 输出语义 yes / no / unknown | 否 |
| `semantic_correct` | semantic_label 与人工真值一致 | 是 |
| `yes_rate` | semantic_label=yes 的比例（**不是准确率**） | 否 |

旧口径缺陷（2026-08-13 审计发现并修复）：原 `parse_yes_no()` 在整行搜 yes/no 词，且旧 `strict_yes_rate` 把合规的 "No." 计为 0（实为"可解析为 Yes 的比例"）；正样本全 Yes 组两值碰巧相等，掩盖缺陷；σ≥7 模糊组与 D@320 组暴露问题。重算脚本 `metrics.py`（22 测试用例）+ `reanalyze_all.py`。

### 3.4 数据质量审计摘要（9 项，详见 data/EXPERIMENT-LOG.md）

1. 历史数据全为单正样本场景 → yes_rate ≠ 准确率；
2. 相邻帧伪重复 → 历史 Fisher 检验降级为探索性（新实验改为同帧配对 McNemar 或冻结帧独立采样）；
3. 跨会话基线漂移（同配置 256M@640 t=0.1 四会话 9%–67%）→ 会话内对照优先；
4. 旧帧采样与轮次无精确关联 → Stage2 起每帧记录 SHA-256；
5. 模糊组缺 videoconvert sham 对照 → σ 效应与管线效应未完全解耦（结论已限幅）；
6. 图文顺序混杂（C text→image vs Python image→text）→ **S2-E1 定位并解决**；
7. 历史实验固定顺序运行 → 与时间漂移混杂；
8. 板端密码硬编码入仓库 → 已标注待换；
9. exp5_A 日志被同名覆盖（45%→9%）→ 已从 git 恢复双版本。

## 4. 结果 (Results)

### 4.1 历史现象（修正口径）

复现组（v0.1, t=0.1, text→image, 问题 A）：

| 模型 | 分辨率 | 轮 | format_word | 语义 Y/N/U |
|------|--------|-----|------------|-----------|
| 256M | 320×240 | 45 | 45/45 (100%) | 45/0/0 |
| 256M | 640×480 | 44 | 16/44 (36%) | 44/0/0 |
| 500M | 320×240 | 39 | 39/39 (100%) | 16/23/0 |
| 500M | 640×480 | 36 | 0/36 (0%) | 36/0/0 |

### 4.2 实验1 分辨率梯度（text→image）——"崩塌"的表观模式

| 模型 | 160×120 | 320×240 | 480×360 | 640×480 | 800×600 | 1280×960 |
|------|---------|---------|---------|---------|---------|----------|
| 256M format_word | 34/34 | 45/45 | 33/33 | 16/44 | 0/32 | 1/32 |
| 256M 语义Y | 0 | 45 | 33 | 44 | 32 | 32 |
| 500M format_word | 29/29 | 39/39 | 24/29 | 0/36 | 0/27 | 0/27 |
| 500M 语义Y/N/U | 1/28/0 | 16/23/0 | 9/20/0 | 36/0/0 | 25/0/2 | 26/0/1 |

要点：256M 表观突变点 480(100%)→640(36%)→800(0%)；500M 漂移更早（480 已有 5 句）；160×120 两模型格式 100% 但语义全 No（感知失败、不幻觉）；耗时全梯度 5.4–6.9s 恒定（token 恒定佐证）。

### 4.3 措辞（实验5, text→image, @640×480, 256M）+ 跨会话漂移

| 组 | 措辞 | 轮 | format_word | 语义 |
|----|------|-----|------------|------|
| A-s1 (08-11) | 基线 | 33 | 15/33 (45%) | 33/0/0 |
| A-s2 (08-12) | 基线重跑 | 32 | 3/32 (9%) | 32/0/0 |
| B | 去 "center" | 33 | 1/33 (3%) | 33/0/0 |
| C | 最简问句 | 33 | 11/33 (33%) | 33/0/0 |
| D | "Does the image contain…?" | 33 | 27/33 (82%) | 33/0/0 |
| E | 约束置句首 | 32 | 3/32 (9%) | 32/0/0 |
| F | 加示例 | 32 | 5/32 (16%) | 32/0/0 |
| G | 500M@320 延长跑 | 39 | 39/39 (100%) | 37/2/0 |

要点：**同配置跨会话漂移显著**（A 组 45% vs 9%；256M@640 t=0.1 四会话 9%/36%/45%/67%）→ 历史各组间 p 值仅具探索意义；措辞方向非平凡（D 探测式 82% vs B 去中心 3%）；G 组 vs 复现组 500M@320 语义 95%↔41% 跨会话不稳定。

### 4.4 温度（实验7, text→image, @640×480）

| 模型 | t=0.0 | t=0.1 | t=0.5 | t=1.0 |
|------|-------|-------|-------|-------|
| 256M format_word | 28/33 (85%) | 22/33 (67%) | 13/33 (39%) | 13/33 (39%) |
| 500M format_word | 0/28 | 0/27 | 0/27 | 3/28（语义 9/4/15） |

要点：256M 温度效应单调（t0.0 vs t1.0 p=0.0003，探索性），但 greedy 仍有 15% 句子 → 采样非唯一因素；500M 崩塌在 t≤0.5 与温度无关（确定性行为），t=1.0 才出现少量单词且语义崩塌。

### 4.5 滤镜变体（实验2/3, 256M, text→image, t=0.1）——修正后：格式从不崩塌，变化的是语义

| 组 | 处理 | 轮 | format_word | 语义 Y/N/U |
|----|------|-----|------------|-----------|
| exp2_B | 640 采集→缩 320 输入 | 33 | 33/33 (100%) | 33/0/0 |
| exp2_C | 320 采集→放大 640 | 33 | 33/33 (100%) | 33/0/0 |
| exp2_D | 640 裁剪中心 320 | 33 | 33/33 (100%) | 33/0/0 |
| exp3_C | 640→160→640 重采样 | 33 | 33/33 (100%) | 33/0/0 |
| σ=1 / σ=2 | 高斯模糊 | 32/32 | 32/32, 32/32 | 全 Yes |
| σ=3 / σ=4 | 高斯模糊 | 32/31 | 32/32, 31/31 | 28/4, 29/2 |
| σ=5 | 高斯模糊 | 31 | 31/31 (100%) | 10/21 |
| σ=7 / σ=15 | 高斯模糊 | 30/28 | **30/30, 28/28 (100%)** | **全 No** |

要点（**与旧报告的重大差异**）：旧口径把 σ≥7 记为"格式 0%"——修正后**所有模糊组格式 100%**；σ 的剂量效应作用在**语义轴**（Yes→No）而非格式轴。"感知失败→单词"与"感知成功+引导式提问→描述句"是两种互斥状态。⚠️ 缺 sham 对照：σ 效应与 videoconvert/重编码管线效应未完全解耦。

### 4.6 耗时与 token 数恒定

全部分辨率/滤镜条件下每轮 5.4–6.9s，无随分辨率的系统增长 → 视觉编码固定开销主导；与 fixed_size 预处理（token 恒定）一致。S2-E2-RES 中 160×120 至 1280×960 全部 6.1s（§4.9）。

### 4.7 静态图对照与 S2-E0 能力探测

- 静态图（image→text, cache_prompt=false, 高细节 640）：30/30 单词全 "Yes."，每轮全量计算 5.9s（cached_tokens=0 验证缓存已关）。
- S2-E0 板端 7af4279 实测能力：**grammar（GBNF）supported**（输出硬约束 Yes./No.）；**cache_prompt=false supported**；**seed supported**（t=0.5 同 seed 两次逐字节一致）；**n_probs supported**（每 token 5 候选+logprob）；response_format json_schema supported（max_tokens=16 有截断风险）；usage/timings 含 cached_tokens。

### 4.8 S2-E1 图文顺序消融（2×2，核心结果）

设计：每场景冻结 20 张连续相机帧（640×480，唯一 SHA），同帧 × 2 顺序配对发送；cache 关、t=0.0、256M、问题 A、每帧顺序先后随机（seed 20260813）。

| 场景 | text→image | image→text |
|------|-----------|------------|
| 负（风扇不在, gt=no） | 0/20 单词；**20/20 幻觉描述句**；sem 0/20 | 20/20 "No."；sem 20/20 |
| 正（风扇在, gt=yes） | 0/20 单词；20/20 描述句；sem 20/20 | 20/20 "Yes."；sem 20/20 |

- 两场景内 McNemar exact p = **1.91×10⁻⁶**（20/20 不一致对同方向）
- text→image 在两种场景输出**完全相同的句子模板**——负场景也断言风扇存在：**引导式提问压倒图像证据（确认幻觉）**
- image→text 40/40 格式合规 + 语义全对
- 历史"静态图不复现、实时帧才复现"的差异由此重解：静态脚本（image→text）永远单词；C 在线链路（text→image）在细节充足时描述漂移——**混杂源是内容顺序，不是输入实时性**

### 4.9 S2-E2-RES image→text 固定下的分辨率重扫（256M 120 请求 + 500M 120 请求）

| 分辨率 | 256M format_word | 256M 语义 | 500M format_word | 500M 语义 | 历史 256M text→image |
|--------|-----------------|----------|-----------------|----------|---------------------|
| 160×120 | 20/20 (100%) | 0/20（全 No） | 20/20 (100%) | **20/20 全 Yes**（稳定场景重跑确认；首跑 17/20 系采集期人为运动干扰，3 个 No 为遮挡真值） | 34/34 (100%, 全 No) |
| 320×240 | 20/20 (100%) | 20/20 | 20/20 (100%) | 20/20（历史摇摆 41%↔95% 消失） | 45/45 (100%) |
| 480×360 | 20/20 (100%) | 20/20 | 20/20 (100%) | 20/20 | 33/33 (100%) |
| 640×480 | **20/20 (100%)** | 20/20 | **20/20 (100%)** | 20/20（历史 0/36 崩塌消失） | 16/44 (36%) |
| 800×600 | **20/20 (100%)** | 20/20 | **20/20 (100%)** | 20/20 | 0/32 (0%) |
| 1280×960 | **20/20 (100%)** | 20/20 | **20/20 (100%)** | 20/20 | 1/32 (3%) |

**"分辨率崩塌"在 image→text 下完全消失**（两模型一致）：全梯度格式 100%、输出严格二值；耗时 256M 恒 6.1s / 500M 恒 7.6s。160×120 呈现**模型规模相关的低端感知阈值**（均为稳定场景采集、帧差验证 <2）：256M 全 "No."（诚实感知失败，不幻觉、不漂移），500M 全 "Yes."（感知保持）。500M@160 首跑曾出现 3 个 "No."——帧差证据（最大 8.99，稳定基线 <2）与现场报告确认为采集期人为运动干扰，稳定场景重跑后 20/20 全 Yes。

## 5. 讨论 (Discussion)

### 5.1 机制链（修正后的因果叙事）

```
图文顺序（主效应, p=1.9e-6）
  ├─ text→image（引导式提问）: 问题预设支配解读
  │    ├─ 高细节（≥640 采集）→ 描述句漂移（"确认+描述"模板）
  │    ├─ 低细节（160/320）→ 退化回单词（细节不足以支撑描述扩展）
  │    └─ 负场景同样断言目标存在 → 确认幻觉
  └─ image→text（观察式）: 图像证据优先
       ├─ 任何细节水平 → 严格二值单词输出
       └─ 细节不足（160/σ≥7）→ 诚实 No（感知失败, 格式仍合规）
```

### 5.2 假设状态

| 假设 | 原表述 | 现状态 |
|------|--------|--------|
| H1 token 膨胀稀释指令 | 分辨率↑→token↑→遵循↓ | **证伪**：fixed_size 预处理 token 恒定（耗时 6.1s 全梯度）；且顺序主效应解释力更强 |
| H2 细节驱动描述先验 | 细节↑→描述输出 | **降级为调节变量**：仅在 text→image 体制内成立；σ 剂量效应作用在语义轴（Yes→No）而非格式轴 |
| H3 容量限制 | 越大模型越稳 | **不支持原表述**：500M 在 text→image 下崩塌更深（greedy 仍 100% 描述句）；两模型行为不同，规模因果未定 |
| H4 位置假设冲突 | "center" 触发纠正 | **证伪简单版本**：去 center（B 组）反而更差；真实因素是问题框架（引导式 vs 探测式 D 组 82%） |
| **新增 H-ORDER** | 图文顺序决定形态 | **强支持**（2×2, p=1.9e-6, 100% 一致性） |

### 5.3 工程启示

1. **部署 yes/no 检测必须 image-first**（改 content 数组顺序，一行改动；v0.3 候选）；
2. **text-first 顺序在小 VLM 上导致确认幻觉**——对安全关键场景是可靠性问题而非格式问题；
3. **grammar 约束在板端可用**：若必须 text-first（历史代码兼容），grammar 可硬保格式；语义正确性需单独验证（下一步 S2-E5）；
4. **评估协议**：静态/在线对比必须固定内容顺序 + 同帧配对 + 记录 cache 状态（cached_tokens 可直接观测）。

### 5.4 与初始论文的关系

初始版本把现象归因于"分辨率→格式崩塌"。本文保留全部原始数据，但通过配对消融证明：**顺序是主效应，细节量是引导体制内的调节变量，分辨率本身无格式效应**。问题性质从"输出格式控制失效"变为"引导式提问下的确认偏误与描述漂移"——后者有更清晰的机制故事与工程解法。

## 6. 结论 (Conclusion)

在 RK3588S + llama.cpp 7af4279 + SmolVLM 栈上：

1. 图文顺序是 yes/no 格式遵循的**完全决定因素**：image-first 下两个模型、6 档分辨率全部 100% 格式合规且语义正确（≥320）；text-first 下 640×480 起系统性地产生描述句；
2. text-first 造成**确认幻觉**：负场景 20/20 断言目标存在，问题预设压倒图像证据；
3. 分辨率、模糊 σ 的效应全部重述为细节量在 text-first 体制内的调节（格式轴与语义轴分离：σ 增加使语义 Yes→No 而格式恒 100%）；
4. 工程建议：**image-first 为默认请求顺序**；兼容场景用 grammar 硬约束；评估必须记录内容顺序、cache 状态与帧哈希。

## 7. 局限性与未来工作

- **单场景/单家族/单板**：全部数据来自一个仓库场景与 SmolVLM 家族；普适性需多场景多类别验证（实验4 跨模型因板端无外网与用户决策删除）；
- **500M 的 image→text 梯度已完成**（§4.9）：≥320 全分辨率格式+语义双 100%，历史摇摆/崩塌消失；160 档两模型差异（256M 全 No vs 500M 全 Yes）已在稳定场景双验证（帧差 <2；污染首跑已重跑排除）；
- **跨会话漂移未建模**：同配置 9%–67%；后续需同会话内嵌对照组；
- **模糊组缺 sham 对照**：σ 净效应未与 videoconvert 管线效应解耦；
- **温度×顺序交互未测**：历史温度扫描全部为 text→image；
- **历史数据单正样本**：旧实验无负样本；新实验（S2-E1/E2-RES）已含正负场景；
- **帧间独立性**：冻结帧来自同场景连续采样，帧级相关；结论依靠 100% 一致性与配对检验，效应量大，但多 session 复现仍必要；
- **参考文献**：仍为占位状态，投稿前需按 methods.md §6 补全（LIMA 应为 NeurIPS 2023）。
