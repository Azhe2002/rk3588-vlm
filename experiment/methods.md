# 调研计划: 输入分辨率对 VLM 输出格式指令遵循的影响

> **状态**: 计划 v0.1
> **日期**: 2026-08-07
> **关联**: paper.md（材料草稿）— 本计划用于验证 paper.md §6 的机制假设并扩展现有数据
> **目标**: 通过受控实验定位"640×480 下 yes/no 约束失效"的根因，产出可发表结论

---

## 1. 研究问题与目标

### 1.1 主研究问题 (RQ1)

**为什么输入分辨率从 320×240 提升到 640×480 时，SmolVLM 系列小模型对 "answer only yes or no" 输出格式约束的遵循率从 90–100% 崩塌至 0–10%？**

### 1.2 子问题

- RQ2: 该现象是否由 **prompt 表述** 引起？（初步答案：否，严厉 prompt 无效）
- RQ3: 该现象是否由 **视觉 token 数量** 引起？（H1）
- RQ4: 该现象是否由 **图像细节/信息量** 引起？（H2）
- RQ5: 该现象是否由 **模型容量/家族** 引起？（H3）
- RQ6: 该现象是否由 **问题措辞中的位置假设** 引起？（H4）
- RQ7: 该现象在**其他任务/模型/输入**上是否普适？

### 1.3 期望产出

1. 根因定位（支持/拒绝 H1–H4 的实证证据）
2. 普适性结论（跨模型、跨任务）
3. 工程建议（如何在高分辨率下维持格式合规）
4. 可发表的论文（基于 paper.md 扩展）

---

## 2. 核心假设 (Hypotheses)

| 编号 | 假设 | 预测 | 支持证据(现状) |
|------|------|------|---------------|
| H1 | 视觉 token 膨胀稀释指令注意力 | token 数↓ → 遵循恢复 | ⚠️ 耗时反证 |
| H2 | 图像细节激活"描述先验" | 细节↓(模糊) → 遵循恢复 | ✅ 500M 输出更具体 |
| H3 | 小模型容量限制下的指令-视觉竞争 | 更大模型 → 遵循改善 | ⚠️ 间接 |
| H4 | 问题位置假设触发"纠正"倾向 | 中性问题 → 遵循恢复 | ⚠️ 500M 全说 foreground |
| H5 | 量化(Q8_0)放大格式退化 | F16 → 遵循改善 | ❓ 未测 |
| H6 | 温度/采样影响 | temp↑ → 遵循↓ | ❓ 未测 |

## 3. 实验设计 (Experimental Design)

### 3.1 实验 1: 分辨率梯度扫描（验证现象的可扩展性）

**目的**: 确认格式遵循随分辨率的退化是"突变"还是"渐变"

| 组 | 分辨率 | 像素数 | 相对 320×240 |
|----|--------|--------|--------------|
| A | 160×120 | 19,200 | 0.25× |
| B | 320×240 (基准) | 76,800 | 1× |
| C | 480×360 | 172,800 | 2.25× |
| D | 640×480 | 307,200 | 4× |
| E | 800×600 | 480,000 | 6.25× |
| F | 1280×960 | 1,228,800 | 16× |

- 模型: 256M + 500M
- Prompt: 普通版
- 每组 ≥20 轮
- **预期**: 若 H1 成立，遵循率随像素数平滑下降；若存在"触发阈值"，则是突变

### 3.2 实验 2: 保持分辨率、改变有效 token 数（判别 H1）

**目的**: 解耦"分辨率"与"视觉 token 数量"

| 组 | 操作 | 分辨率 | 有效 token |
|----|------|--------|-----------|
| A | 原图 640×480 | 640×480 | 多 |
| B | 640×480 图像在**输入前缩小到 320×240**（图像处理层） | 实际 320 | 少 |
| C | 320×240 图像**放大到 640×480**（插值） | 显示 640 | 多 |
| D | 640×480 裁剪中心 320×240 区域 | 320 | 少 |

- **关键对照**: B vs C —— 若遵循率只跟"实际喂入模型的像素"走（B 恢复、C 失效），则 token 数为主因（支持 H1）
- 实现: 用 `v4l2-ctl --set-fmt` + 图像缩放/裁剪管道

### 3.3 实验 3: 模糊/噪声扰动（判别 H2）

**目的**: 保持分辨率不变、消除可描述细节，看遵循率是否恢复

| 组 | 处理 | 细节水平 |
|----|------|---------|
| A | 原图 640×480 | 高 |
| B | 高斯模糊 (σ=3, 7, 15) | 中→低 |
| C | 下采样后再上采样（去纹理） | 低 |
| D | 添加强噪声 | 低 |
| E | 纯色背景 + 目标轮廓（极简） | 极低 |

- **预期**: 若 H2 成立，细节↓ → 遵循率↑（模型"没话可说"就回到单字）
- 实现: 板端 OpenCV 或预处理阶段处理帧

### 3.4 实验 4: 模型容量/家族扩展（验证 H3 + 普适性）

| 模型 | 参数量 | 架构 | 来源 |
|------|--------|------|------|
| SmolVLM-256M | 0.25B | SmolVLM | 已有 |
| SmolVLM-500M | 0.5B | SmolVLM | 已有 |
| Qwen2-VL-2B | 2B | Qwen2VL | 已转换 (941M Q4) |
| Moondream2 | 1.9B | Moondream | 已有 (877M Q4) |
| (可选) SmolVLM-2.2B | 2.2B | SmolVLM2 | 需下载 |

- 同任务、同分辨率矩阵，对比遵循率
- **预期**: 若 H3 成立，更大模型在高分辨率下遵循率更高

### 3.5 实验 5: 问题措辞（判别 H4）

| 组 | 问题 | 位置假设 |
|----|------|---------|
| A | "Is there a black industrial fan **in the center** of the image?" | 有 |
| B | "Is there a black industrial fan in the image?" | 无 |
| C | "Is there an industrial fan?" | 无 |
| D | "Does the image contain a black industrial fan?" | 无 |
| E | 指令后置: "... Please answer only yes or no." 与 指令前置 | — |
| F | 加 few-shot 示例（"Example: Yes"） | — |

- **预期**: 若 H4 成立，中性问题 (B/C/D) 遵循率显著高于 A；若 few-shot (F) 显著提升，说明指令遵循可通过示范强化

### 3.6 实验 6: 解码约束（工程解法验证）

| 组 | 方法 | 实现 |
|----|------|------|
| A | 基线（自由解码） | 现状 |
| B | max_tokens=2 | llama-server 参数 |
| C | logit 掩码强制 yes/no | 需改 llama_infer 或 server |
| D | 后处理语义解析兜底 | parse_yes_no_lenient (已实现) |

- **目的**: 为工程应用提供"高分辨率 + 严格格式"的可行解
- 记录各组格式合规率与语义正确率

### 3.7 实验 7: 温度/采样扫描（验证 H6）

- 温度: {0.0, 0.1, 0.5, 1.0}
- top_p: {0.9, 1.0}
- 分辨率: 640×480, 模型: 256M
- **预期**: 温度升高 → 遵循率下降（低温度更守格式）

### 3.8 实验 8: 量化影响（验证 H5）

- 256M: Q8_0 vs F16（如可转换）
- 500M: Q8_0 vs F16
- 640×480, 普通 prompt
- **预期**: 若量化损伤指令遵循，F16 应显著改善

### 3.9 实验 9: 注意力量化（H1 的直接验证，可选）

- 若 llama.cpp 暴露注意力权重（或改用 Python 推理栈），统计:
  - 指令 token 的平均注意力权重（320 vs 640）
  - 视觉 token 数量与指令注意力占比的相关性
- **预期**: 640×480 下指令 token 注意力占比显著下降

## 4. 数据收集协议

### 4.1 每轮记录字段

```
timestamp, model, resolution, prompt_version, temperature,
frame_jpeg_md5 (去重校验), latency_s, raw_output,
strict_parse_result, semantic_parse_result, output_type
```

### 4.2 样本量

- 每组 ≥20 轮（现状 10 轮，为统计功效提升至 20-30）
- 关键对照（实验 2/3）≥30 轮
- 统计检验: 组间遵循率用 Fisher exact test / chi-square；耗时用 Welch's t-test / Mann-Whitney U

### 4.3 数据存储

```
rk3588-vlm/experiment/
├── data/                 # 结构化结果 CSV/JSON
│   ├── exp1_resolution/  # 每组一个 csv
│   ├── exp2_tokens/
│   └── ...
├── plots/                # 图表
├── paper.md
└── methods.md
```

### 4.4 工具链

- 板端: rk3588-vlm（已支持 --width/--height/--question/--strict）
- 记录: 扩展 main.c 或写独立采集脚本（输出 JSONL）
- 分析: 本地 Python + pandas + matplotlib
- 图像处理: OpenCV（模糊/缩放/裁剪）

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 板端无外网（模型下载受限） | 模型扩展受限 | 优先用本地已有模型；必要时经代理下载 |
| llama.cpp 不暴露注意力 | H1 直接验证受阻 | 用 Python 推理栈 (transformers) 做单次对照 |
| 图像预处理管道开发量大 | 实验 2/3 延期 | 先做 3.2-B/C 最小对照（缩放即可验证） |
| 每组 20 轮样本仍少 | 统计功效不足 | 关键对照加至 50 轮；报告效应量 |
| 现象可能是 SmolVLM 特有 | 普适性存疑 | 实验 4 跨模型验证，论文如实报告范围 |
